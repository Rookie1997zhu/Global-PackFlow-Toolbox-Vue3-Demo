01

先看结论：下一版要解决什么

建议将 PackFlow 从“多功能包装与物流计算器”收敛为 “韩国中小出口企业的包装、装载与出货资料辅助工作台”。工具仍然独立使用，但结果应当容易导入、验证、保存和交付。

3Demo → 全栈 MVP → 商业 SaaS 阶段
我最建议投入的三件事① 修复计算与多语言导出中的可信度缺口；② 为韩国用户优化装柜 / 卡板 / P/L / Invoice / 对账交付体验；③ 把韩文真实内容、工具独立页面及 Naver 可索引性建立起来。

重要边界：“韩国中小出口企业愿意使用这一组合”是有行业依据的产品假设，而不是已经被访问量或用户访谈证明的事实。此报告明确区分代码事实、外部公开事实和策略推断。

韩国市场：为什么值得做，以及先服务谁

279,651韩国 2025 年有贸易活动的企业数（关税厅公布）[S1]
80,4902026 上半年有出口业务的中小企业数（MSS，暂定）[S2]
19,7462025 年“首次出口”企业数，按关税厅特定定义 [S3]

上述统计证明韩国有规模可观的出口企业群体，但不能直接推算 PackFlow 可获得的付费用户数量。真正的切入点是其中需要反复编制包装、装载、出货资料的小团队。

优先用户 A · PRIMARY

中小型出口公司业务/贸易负责人

需要整理多 SKU 装箱资料，与货代、仓库、买家交换 Excel/PDF，并比对 Invoice/Packing List。

搜索动机：패킹리스트 작성, 인보이스 패킹리스트 대조, CBM 계산기
优先用户 B · PRIMARY

制造商 / 包装与出货负责人

反复计算卡板装载、集装箱空间、纸板用量，并需要能交付给仓库的摆放图。

搜索动机：컨테이너 적재, 파렛트 적재 계산기, 박스 원단 재단
第二阶段 C · SECONDARY

货代 / 物流营业人员

关注计费重、最低收费、各家报价包含的项目、客户可读报告。暂不追求实时运价。

搜索动机：운임중량 계산, 물류비 비교, CBM 계산
第二阶段 D · SECONDARY

品牌方 / 包装设计与工厂

关注韩国本地常见包装结构、展开刀版、实际工艺补偿和可用于沟通的文件。

搜索动机：박스 칼선, 패키지 전개도, 지기구조
韩国版最强的首个产品任务（建议）엑셀 업로드 → 적재 계산 / 서류 대조 → 한국어 PDF 보고서
即：上传 Excel 货物清单 → 生成装载或核对结果 → 输出韩文报告。
注意：这是一条可选捷径；每个工具仍必须允许独立使用，不强制进入一整套 ERP 流程。

韩国竞品：别把“3D 与刀版”当成独占功能

竞品 / 示例公开展示的能力PackFlow 应该怎样错位竞争
CAYS [S4]在线刀版 PDF、3D 预览、实时包装报价与下单不与包装制造下单平台硬碰；强调中立的免费规划工具与可导出数据
Packative Studio [S5]3D 包装设计、AI 设计草案及订单衔接强调真实工程参数、装载结果及文档核对，不以 AI 设计噱头竞争
MyHomeLab [S6]韩语卡板/集装箱 3D、旋转与分层查看、可打印指示书、韩国 T11升级多 SKU 批量导入、核对与跨工具成果交付；不能只宣传“有 3D”
AZ 계산기 [S7]免费 T11 卡板计算、一层数量与层数把实际排布、复杂约束和报告做深，而不是重复格子计算
유비스관세사무소 [S8]在线填写 Invoice / Packing List提高 Excel 双表校验、字段映射与错误解释能力

这是一组经公开页面核查的竞争样例，并非全市场份额排名；部分网站是制作服务、部分是免费工具，商业模式不同。

建议的差异化定位

韩国市场不要把 PackFlow 当成“另一个在线包装下单平台”。你暂时没有制造网络、报价履约或实时物流数据。更适合的定位是“不绑定任何包装厂与货代、浏览器即用、可导出专业计算/核对结果的中立工具平台”。

06

韩国版该重点打磨的 5 个核心体验

A · 首要

韩式货物 Excel 导入与字段映射

支持 Korean / English 表头，例如 품명、규격、수량、박스수、총중량、순중량、가로/세로/높이、CTN NO。导入时预览前 10 行，允许用户选择列，清楚标出空值、单位不明、重复箱号。

目标：输入成本降到最低，尤其是不用人工重新输入旧表格。
B · 首要

韩文 Packing List + Invoice 差异核对

按 PO、SKU、箱号或自定义匹配键核对；支持缺失、重复、数量差、单位不一致、金额差、重量差；输出“错在哪里、去哪里改”的报告。

韩国关税厅与贸易协会均强调装箱资料和商业发票内容应一致。[S9][S10]
C · 首要

装柜 / 卡板装载结果可执行

默认韩国常用 T11 1100×1100mm，并提供 T12、自定义；保留 2D/3D，重点显示未装 SKU、超重、空间限制、分层示意及可打印装载指导。

与韩国免费 3D 竞品相比，价值要落在 Excel → 分析 → 现场交付。
D · 首要

韩文字体与 A4 输出

PDF 的韩文、韩元、公司地址、买家姓名必须正确显示；长表格自动分页，页码与总计一致；CSV 能直接被韩国常见 Excel 工作流正确打开。

韩语市场最基础的信任门槛：内容不能出现乱码或截断。
E · 次优先

物流报价成本透明化

允许手动输入 KRW/USD/CNY 及汇率、起运地/目的地、报价有效期、包含/不包含项目；未完成币种归一时禁止直接判“最低价”。

暂不做“全韩国物流商实时运费”，避免缺数据却假装精确。
F · 次优先

纸板排版与刀版的韩国本地表述

区分 박스 칼선、전개도、지기구조、원단 재단、판짜기；添加常见样例及材料工艺说明，不能把 3D 视觉预览直接等同于生产验证。

优先面向懂包装的人，别为“包罗万象”牺牲准确性。

07

韩国本地化：不只是把中文翻译成韩语

UI / 数据层面

  • 韩国入口默认韩语，并记住用户选择；其它语言仍可切换。
  • 货柜、尺寸支持 mm / cm；重量 kg；金额按 KRW 的分组显示，例如 ₩1,250,000。
  • 默认 T11、T12 卡板；真实尺寸可编辑，并提示不同仓库、承运商可能不同。
  • 韩国专业词汇由母语贸易/包装从业者审校，避免中式韩语。
  • 韩语公司名/地址及 Unicode 内容必须在 CSV、XLSX、PDF 和打印中完整保留。
  • 对输入给出具体错误：例如“총중량이 순중량보다 작습니다”（毛重小于净重）。

Naver / 搜索获取层面

  • 将关键工具做成独立韩语 URL，页面可由搜索机器人看到正文，不只依赖前端 JS。
  • 设置韩语页面 title、description、lang=ko、内部链接与 sitemap.xml。
  • 注册 Naver Search Advisor，验证站点所有权，提交 sitemap，检查索引/抓取问题。[S11]
  • 英文和中文继续保留不同语言 URL，配置合理的 hreflang。
  • 每页写公式、输入例子、限制说明和截图，不用机器翻译堆砌内容。
  • Google / Naver 搜索结果都需要实际查询验证，不保证提交就会有流量。

建议 V1.2 四轮迭代：先可靠，再本地化，再推广

迭代 1 · P0 正确性与韩文输出

交付：修复跨币种最低价、体积重规则选择、刀版语言映射；建立完整韩文 PDF 字体与分页；修正 .xls 文件入口。

结束条件：韩文输入与导出无乱码；不再出现币种直接比较或计费模式误导。

迭代 2 · 韩国实际 Excel 与单据核对

交付：韩语表头模板、字段映射、导入预览、异常行定位；Packing List / Invoice / 对账的一键示例数据与报告。

结束条件：真实韩国格式文件可以导入、核对、下载完整差异报告；错误原因可理解。

迭代 3 · 装柜与卡板的专业成果

交付：T11/T12 预设、多 SKU 导入、未装原因、分层可打印装载报告、Demo 本地方案备份，并定义正式版云端方案 API 契约；明确几何建议与现场安全验收的边界。

结束条件：用户能把报告发送给仓库并理解每一步，而非只看 3D 动画。

迭代 4 · 韩国搜索落地与真实用户测试

交付：独立韩语工具静态页面、Naver Search Advisor、韩文教程与 FAQ、真实任务测试以及源码 README 更新。

结束条件：韩语页面可直接访问与刷新、静态 HTML 可见；真实使用者有任务结果与反馈记录。

现在不做为什么后续触发条件
真实收费、注册、团队权限当前不作为 Demo 交付范围，但必须预留后端认证、权限、计费接口进入正式 SaaS MVP 阶段，并完成权限与支付方案设计
韩国所有物流商实时运费规则、合同价、实时价格缺失有正式 API 数据合作
AI 自动识别 PDF/扫描件先解决结构化 Excel 的可靠性实测出现大量非结构化资料需求
更多简单工具数量同类市场已有大量免费工具现有核心工具被持续复用后
生产级刀版与装载安全背书必须结合材料、现场和工艺测试完成实物验证和专业责任边界

如何验证韩国用户真的愿意使用

建议优先找 5–8 位符合岗位的韩国用户做探索性任务测试：中小出口公司的贸易/出货担当、仓库装载担当，以及包装厂技术/设计人员。人数是初期研究建议，不是具有统计代表性的样本。

任务 A

真实包装清单 → 装柜规划

拿一份实际 Excel，让受试者独立完成装柜，告诉他哪些 SKU 未装下，能否生成可用的指导文件。

观察：手工调整列耗时、正确率、报告是否能直接交给仓库。
任务 B

Invoice + P/L → 差异核对

提供两份带数量/箱号错误的韩文样例，要求用户找出问题并输出差异说明。

观察：匹配字段是否自然、错误是否解释清楚、是否愿意用于实际工作。
任务 C

卡板规划 → 现场说明

按韩国 T11 卡板及实际箱规生成排布，要求用户解释摆放图，并指出安全约束未覆盖之处。

观察：不懂算法的人能否理解 2D/3D，是否误认“建议”为“安全认证”。
任务 D

韩国搜索 → 直接进入目标工具

让用户选择自己最可能输入的搜索词，从直接链接进入工具，不经首页也能完成任务。

观察：术语是否准确、首屏 CTA 是否显眼、是否需要韩语帮助文本。

建议记录的成功指标（试验门槛，不是行业基准）

指标初始观察目标怎么测
首次示例到结果30 秒内计时：加载示例到理解结果
真实任务完成率至少 80%不经开发者指点完成任务
导出成果可用率至少 80%韩文 PDF / Excel 不需再人工重做
准确性回归关键黄金样例 100% 通过算法单测 + 人工校对
再次使用意愿至少 60%任务结束后访谈记录

交付验收清单

  • 韩语界面没有突然切回中文的模块；韩国语用词经母语用户复核。
  • 含韩文公司名称、品名、地址的 PDF 多页打印正常；CSV/XLSX 在韩国常见 Excel 环境中测试。
  • 报价比较在币种不同且未换算时，不提供错误的最便宜排名。
  • 体积重可明确选择逐件 / 分组 / 整票模式；输出计算依据。
  • 装柜与排版算法的所有已放置物体无越界、无相交，且未装货物数量守恒。
  • 韩国 T11/T12 及自定义规格可用；默认值不代表所有场景。
  • 刷新与恢复方案不丢失用户合理输入；清除浏览器存储风险有提示。
  • 工具独立 URL 可直接打开、刷新；静态 HTML 包含韩文内容与元信息。
  • README 与最新代码功能一致；构建、测试和部署可复现。

修订：从前端 Demo 演进为正式商业化 SaaS

架构定位修订：纯前端是当前开发与演示方式，不是 PackFlow 的最终产品形态。正式上线应采用完整前后端架构，支持韩国市场先行、后续全球扩展。不要因为当前没有后端而删减正式产品的核心能力。

阶段主要交付数据与计算方式成功标准
阶段 A · 当前 DemoVue 3 / TypeScript 工具功能、算法验证、韩语 UX、Excel / PDF 样例、可复现测试浏览器状态、可选 IndexedDB / JSON；Web Worker 运行可承受的算法核心场景可用，算法规则明确，真实用户能完成测试任务
阶段 B · 韩国市场全栈 MVP账号登录、云端项目/方案、文件上传、计算任务、历史版本、韩文报告、基本管理后台Vue 3 + TypeScript；建议 Django DRF + PostgreSQL + Redis + 对象存储；异步任务队列韩国试点客户可以持续使用、跨设备恢复、按权限共享和追溯计算
阶段 C · 商业化 SaaS订阅或按次付费、团队席位、组织权限、用量配额、账单、审计日志、监控与运营正式认证授权、服务端计费校验、异步任务扩缩容、备份与恢复真实付费、稳定运行、可运营且满足隐私和数据保留要求

建议的系统分层（技术选型为建议，不是已实现）

Frontend  Vue 3 + TypeScript
  ├─ 工具 UI / 2D-3D 可视化 / i18n / Excel 与 PDF 预览
  ├─ Tool API Client（从 Demo 阶段开始统一请求接口）
  └─ 轻量本地计算 + 任务进度与错误反馈
                    │ REST / 可选 WebSocket 或轮询
Backend   Django REST Framework（建议）
  ├─ 用户 / 组织 / 角色 / 权限
  ├─ 项目与方案版本 / 共享链接 / 文件元数据
  ├─ 计算任务 API / 结果存储 / 报告生成
  ├─ 订阅、额度、订单和支付状态校验（商业阶段）
  └─ 管理后台 / 审计 / 日志
Infrastructure
  ├─ PostgreSQL（业务数据） + Redis（缓存/队列）
  ├─ Celery 等任务队列（大型装柜、排版和批量报告）
  ├─ S3 兼容对象存储（用户文件、导出报告）
  └─ Docker Compose 起步；按业务增长扩展部署

计算引擎：保留现有投资，按负载逐步迁移

保留当前 TypeScript 算法作为可复用的规则基线与浏览器端快速预览。为每个计算任务定义版本化输入、输出、单位、约束和错误码；大型多 SKU 优化与批量运算可迁移至服务端 Worker。迁移时用相同黄金样例比较结果，不应为了使用 Django 而无条件重写所有计算逻辑。

韩国市场正式上线的额外要求

  • 账号与组织：支持个人与企业团队，数据按组织隔离，权限在后端执行。
  • 韩语体验：韩文界面、报告、通知与客户支持；KRW 为韩国市场默认展示币种，但保留多币种和明确汇率来源。
  • 隐私与安全：根据实际处理的个人信息、跨境数据传输和服务条款，核对韩国适用法律要求；不能把前端本地存储当作正式数据保护方案。
  • 支付：正式商业化前调查韩国企业客户常用的支付、税务凭证和结算方式；支付服务商及本地合规细节需单独核实。
  • 搜索：公开韩语工具页继续采用可索引的静态/服务端渲染内容；登录后的项目与客户数据不应公开索引。
关键决策当前 V1.2 仍可优先打磨 Demo 工具，但正式产品需求应同时进入后端 API、数据模型与权限设计。
不要将“当前不做后端”误写成“未来不需要后端”。
